# Agent rules for sr-drawing-pack

This is the only agent rules file in the repo. Do not add a CLAUDE.md or any other agent file; put rules here.

## Read first, before starting work or asking
Before starting work or asking the maintainer anything, read in order: (1) this repo's agent guide
(`AGENTS.md`), (2) its decisions file `docs/DECISIONS.md`, (3) the project's live state in
this repo: `STATE.md` and this branch's `STATE-<slug>.md` at the repo root, (4) the notes in the
shared store, `<Projects>\_claude\Claude Projects\Working Memory\memory\sr-drawing-pack\INDEX.md` (WSL:
that same folder under the Windows Projects root; preferences, machine facts, gotchas). If a rule or note already answers a question, act on
it and cite it - never ask the maintainer something the rules already answer.
Tiers (decision 2026-11-22): this repo holds the router `AGENTS.md`, SPEC, DECISIONS, rules, data and
live state (`STATE.md`, `STATE-<slug>.md` committed on its branch, `BACKLOG.md`, `archives/`); the
store folder holds notes only; `TASK.md` is the branch checklist at the worktree root, git-ignored.
At 80% context, run `state-closeout` (closeout mode); on-demand handoff: `state-closeout handoff`; no
`HANDOFF` or `handoffs/` files (`STATE-<slug>.md` is the handoff). A PR's last commit archives the
state file. Store unreachable (PC offline, cloud session): live state is still in the repo. Claude desktop online Memory is a
separate account-level list and is not this store.
Project memory: <Projects>\_claude\Claude Projects\Working Memory\memory\sr-drawing-pack\INDEX.md

## Read order

## Map
- `SRDrawingPDF/`: the Fusion add-in (sheet engine `sheet2d/`, view engines `vieweng/`, XQ = exact lines). Keep it
  self-contained so the AddIns junction works. `tests/`: pytest suite. `tools/check.py`: the repo check CI runs.
  `dev/`: local helpers (sheet demo, title editor, timing). `docs/engine/`: install, usage, editor docs.
- `.claude/rules/drawing-engine.md`: how the engine must draw (read before changing `SRDrawingPDF/`).
- `viewer/index.html`: view-only 3D model viewer for vault items (ADR-066). Opens a GLB made by
  `python -m vieweng.glb model.step model.glb` (run in `SRDrawingPDF/`). Its hardware name rule mirrors
  `sheet2d.meshparts.is_hardware`; change both together.
- `.claude/rules/drawing-style.md`: how every sheet is made (read before making a drawing).
- `docs/RESEARCH.md`: test evidence. `docs/REFERENCES.md`: read-only sources and licenses. `docs/DATA-CARD.md`: superseded by ADR-032; kept as reference for any repo that wants it (Daniel, 2026-11-23, H39; ADR-043).
- `research/fusion-tests/`: one-off test scripts. They need the `SRDP_ROOT` environment variable (path to your clone).
- `research/spike-b/`: spike B scripts. `views_row.py` and `styled_sheet.py` need `HBCAD_ROOT` (path to a handbuilt-cad clone) and that clone's Python.
- `research/editor-slice/`: first clickable editor screen (local web page + server). `research/assembly-test/`: test assembly and its drawing package. Each has a README.
- `research/fusion-data/`: retired (ADR-029); the data file is sr-export's `<name>.bom.json`.
- `research/thumbnails/`: BOM thumbnails from a STEP with the F3D viewer. Needs `F3D_EXE` (path to f3d.exe).
- `research/real-test/`: whole-chain test on a real Fusion design, and the hidden-line speed test (`hlr_speed.py`).
- `research/render-tests/`: render-mode tests on real models. `xq_render.py` is the XQ modes (ADR-052); `xq_sheet.py` makes
  a sheet (PDF, DXF, PNG) and the sparkCAD hand-over record from a STEP. Needs `HBCAD_ROOT`; `F3D_EXE` optional.

## Coordination
- One coordinator chat owns the root STATE. Workers are dispatched from it, one branch each, each with
  its own `STATE-<slug>.md` committed on that branch (coordinator-kit).
- Every repo change goes through safe-repo-preflight: branch, checks, PR.
- Before pushing a follow-up commit to a branch, check its PR is still open.

## Public repo
- Never commit secrets, tokens, personal or machine paths (drive letters, user names), or vendor CAD
  files (STEP, f3d, SLDPRT and the like). Use relative paths or `SRDP_ROOT`.
- Read-only sources are listed in `docs/REFERENCES.md`. Copy in under their license; never edit them.

## Git
- Work on a branch and open a PR. Never commit to `main`. Pulls are fast-forward only. Never force-push.
  Never skip a hook.
- Standing merge permission (Daniel, 2026-11-25): an agent merges its own PR as soon as CI is green and every hook and gate passed, without asking, then deletes the merged branch (remote and local) and fast-forwards `main`. Never with a red or skipped check, never by bypassing a gate, never a force-push.

## Scope
- This repo is only the drawing generator: make rule-following drawings, give the editing features, and
  export the needed file types (ADR-012, ADR-020).
- Vault, numbering, approval workflow, check-in/out, rev stamping and fab-floor viewing belong to the
  separate sparkCAD / PDM app (product data management, being built elsewhere per Daniel 2026-11-19; its repo and owner are not visible from this workstation; not the `custom-pdm` power distribution repo). Do not plan or build those here. Expose clean hooks instead, for example
  "re-export with rev X filled in".
- Flag anything that drifts past that before building it.

## Engine checks
- Run `python tools/check.py` before every push (on Linux with no screen: `xvfb-run -a python tools/check.py`).
  CI (`checks.yml`) runs the same check. It scans for secrets, machine paths, vendor CAD files and banned words.
- Engine timing runs use a scratch clone, never the clone Fusion loads the add-in from.

## Live Fusion tests
- Never walk the Fusion cloud hub recursively. A recursive scan crashed Fusion once.
- Never close, save over or change the user's open documents. Open a scratch document whose name
  starts with `SRDP_SCRATCH`, and close only that.
- Never call sheets or views APIs on a drawing that has no model reference. It hung Fusion once.
- `execute_python` runs on Fusion's main thread: a hang kills the MCP. Keep calls short.
- Local Fusion Desktop has its own app lock, `fusion-desktop` (ADR-054): take it before a script run in the Fusion app or
  driving the app, check in every 10 min, release when done (workstation `instructions/projects-AGENTS.md`, section 5).
- Tests and exports use local desktop Fusion, the way engineers will use the app, not Fusion Compute (ADR-042).
- Do not start or stop the workstation workers.
- Nothing is installed into Fusion's AddIns folder until Daniel approves an iteration. When approved,
  install by a directory junction from AddIns to the add-in folder in the clone (same as sr-bom,
  sr-export, sr-fastener). For this repo the junction is named `SRDrawingPDF` and points at the `SRDrawingPDF`
  folder in the clone, never the repo root (`docs/engine/ADDIN-README.md`). `pull.cmd` updates the clone.
- Smoke tests close their own design without saving.
- Never run Fusion or CAD jobs on DRG-Laptop. Work-PC jobs run under keep-awake. No part IDs in chat.
